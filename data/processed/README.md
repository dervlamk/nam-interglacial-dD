# data/processed — timeslice-mean proxy δD

Timeslice-mean proxy hydrogen isotope (δD) records used in the notebooks to compare against
simulated precipitation δD. All three files cover the same two cores. `..._dDp.csv` and
`..._dDraw.csv` carry five timeslices as of 2026-08-09 (late Holocene, Holocene, LGM, LIG, PGM);
the stale `..._dD.csv` still has the original three (Holocene, LGM, LIG).

## Files

- `timeslice_mean_proxy_dDp.csv` — **δD<sub>p</sub>, and what both model notebooks read**
  (`LGM_analyses.ipynb`, `LIG127k_analyses_PALEOCALADJUSTED.ipynb`). The model quantity they
  compare against is itself δD of precipitation, so comparing δD<sub>wax</sub> to model
  δD<sub>p</sub> would leave the leaf-wax/precipitation offset in the comparison. The LIG
  notebook read `..._dDraw.csv` until 2026-08-10; it no longer does.
- `timeslice_mean_proxy_dDraw.csv` — as-measured δD<sub>C30</sub>. Still what the proxy-side
  figure notebook (`dDwax_timeslice-means_timeseries.ipynb`) writes and plots; no model notebook
  reads it.
- `timeslice_mean_proxy_dD.csv` — the older 3-timeslice file, on the pre-2026-08-09 header
  (`_1serr`, `holocene_*` for the 0–4 ka window). Read by nothing.

The two files' δD values differ by a near-constant offset of about **+91 to +92‰**
(`dD ≈ dDraw + ~91‰` for every cell). That consistent offset is in the range typical of the
apparent fractionation between a leaf-wax biomarker's measured δD and its source/precipitation
water δD — which would make `dDraw` the as-measured proxy values and `dD` a source-water-corrected
version.

**Confirmed (2026-08-05).** That inference was right. Both files are written by
`dDwax_timeslice-means_timeseries.ipynb`, from two adjacent cells:

| | `timeslice_mean_proxy_dDraw.csv` | `timeslice_mean_proxy_dD.csv` |
|---|---|---|
| Quantity | δD<sub>C30</sub> — as-measured leaf wax | δD<sub>p</sub> — precipitation, after the C3/C4 ε correction |
| Mean over | `.mean(dim=['age'])` | `.mean(dim=['ensemble_n_dDp','age'])` |
| Error column | `.std(dim=['age'])` | `.std(dim=['ensemble_n_dDp','age'])` |
| Cell status | **live** | **commented out, marked `-----> DON'T USE`** |

Two independent signatures confirm it. The offset (+91.3 to +92.5‰) is the apparent
fractionation ε applied by `scripts/matlab/dDp_epsilon_calculation.m` as
`(1000 + δD) / (ε/1000 + 1) − 1000`, with ε a C3/C4 mixture of −107.8‰ (C4) and −82‰ (C3).
And every error column grows, because the δD<sub>p</sub> version includes the 2500-member
Monte Carlo ensemble dimension — most tellingly NH22P Holocene, which goes from **0.00**
(a single sample in the 0–4 ka window, so zero spread over `age` alone) to **3.30**.

**Superseded 2026-08-10.** That advice ("keep reading `dDraw`") applied when the only
alternative was `..._dD.csv`, written by a cell its author had disabled. `..._dDp.csv` is a
different, live export, and it is what the model notebooks read now — see "Files" above.

  California. C30 fatty-acid methyl ester δD, ice-volume-corrected against the LR04 benthic
  stack, on Bacon age models (see `dsdp-480-479_age-model.ipynb` for the 480/479 splice).
- **Timeslice windows:** late Holocene 0–4 ka, Holocene 0–11.7 ka, LGM 18–24 ka,

  the `fig3` time series; it is exported alongside the 0–4 ka window rather than replacing it.

- **Generated by:** `dDwax_timeslice-means_timeseries.ipynb`, August 2025; header and interval set revised
  2026-08-09 (see "Columns").

## A caveat when comparing against the model — superseded 2026-08-13

This section used to argue that `dDraw` was a defensible input for the model comparison because
the ε offset largely cancels in an anomaly, while warning that ε varies between timeslices and
leaves a residual of ~1.15‰. **Both halves are now out of date, in opposite directions.**

The variable-ε argument described `dDp_epsilon_calculation.m`, which derives ε per sample from a
C3/C4 mixture driven by δ¹³C prescribed per climate state. That script was never adopted and its
output is read by nothing (see `CLAUDE.md`). The **live** pipeline —
`dDwax_data_processing_{nh22p,d480_d479}.m` — applies a **constant ε = −97 ± 2.98‰** as one
shared draw per Monte Carlo iteration, identically across every timeslice. Under a constant ε
there is no per-timeslice residual to worry about.

And the question is moot for the model comparison anyway: since 2026-08-10 both model notebooks
read `..._dDp.csv`, not `..._dDraw.csv`, so no ε cancellation is being relied on.

What the constant shared ε *does* buy is a clean uncertainty on an anomaly: differencing two
windows member by member cancels the shared ε draw almost exactly, leaving essentially the
propagated 2‰ analytical noise. That is what the `_stddev_mc` columns below carry.

## Columns

| Column | Description |
|---|---|
| `core_name` | Identifier for the sediment/ice core or site |
| `lon`, `lat` | Site coordinates (decimal degrees; `lon` in -180:180 convention) |
| `late_holocene_dD`, `late_holocene_dD_stddev` | Late Holocene (0–4 ka) timeslice mean δD (‰) and standard deviation |
| `holocene_dD`, `holocene_dD_stddev` | Holocene (0–11.7 ka) timeslice mean δD (‰) and standard deviation |
| `lgm_dD`, `lgm_dD_stddev` | LGM (18–24 ka) timeslice mean δD (‰) and standard deviation |
| `lig_dD`, `lig_dD_stddev` | LIG (117–130 ka) timeslice mean δD (‰) and standard deviation |
| `pgm_dD`, `pgm_dD_stddev` | PGM (135–150 ka) timeslice mean δD (‰) and standard deviation |

**Two things changed in the header on 2026-08-09; both matter when reading older code.**

*`_1serr` → `_stddev`.* The column was never a standard error. It is
`dDraw.std(dim=['age'])` — the standard deviation of the samples that fall inside the window,
i.e. the spread of the data, not the precision of the window mean. The old name overstated that
precision by √n. **No value changed**, only the name.

*`holocene_*` → `late_holocene_*`, and `holocene_*` reused for a different window.* The column
this file has always carried is the **0–4 ka** mean; `fig3` now calls that window
`late-holocene` and defines a separate, wider `holocene` = 0–11.7 ka. The export was repointed
so that the historical numbers stayed put under the new name — `late_holocene_dD` is
bit-identical to the old `holocene_dD` for both cores. `LGM_analyses.ipynb` and
`LIG127k_analyses_PALEOCALADJUSTED.ipynb` were updated to read `late_holocene_dD`, so their
anomalies are unchanged.

> Anything still reading `holocene_dD` by that name is now differencing against 0–11.7 ka, not
> 0–4 ka. For DSDP-480/479 that shifts the LGM anomaly from −6.98‰ to −7.96‰ and the LIG
> anomaly from +0.19‰ to −0.79‰ — a sign flip. Check which window you want.

`holocene` (0–11.7 ka) and `pgm` (135–150 ka) are exported here for the first time; nothing
downstream reads them yet.

### Anomaly columns — specified 2026-08-13, not yet written

These are **appended** to the existing 13 columns of `..._dDp.csv` and `..._dDraw.csv` by
`dDwax_timeslice-means_timeseries.ipynb` cell 3. No existing column is redefined — this file has
been bitten by a silent redefinition before (see the `holocene_*` note above). `{interval}` runs
over `lgm`, `lig`, `pgm`; the reference window is always `late_holocene`.

| Column | Description |
|---|---|
| `{interval}_n`, `late_holocene_n` | Number of samples inside the window |
| `{interval}_minus_late_holocene_dD` | Window mean minus the 0–4 ka window mean (‰) |
| `{interval}_minus_late_holocene_dD_stddev_samples` | Quadrature sum of the two windows' `_stddev` columns |
| `{interval}_minus_late_holocene_dD_stddev_mc` | Standard deviation of the ensemble of member-by-member window-mean differences |

**The two σ are different quantities and the names must stay distinct.**

- `_stddev_samples` is the spread of the *data* — how much δD varies between samples inside the
  windows. It is the proxy analog of the model's interannual spread, which is what makes it the
  right one to set beside the model error bar.
- `_stddev_mc` is the uncertainty on the *window mean*, propagated through the Monte Carlo
  ensemble. Because ε is one shared draw per iteration, differencing member by member cancels it
  almost exactly, so this is essentially the propagated 2‰ analytical noise. It is small but
  strictly nonzero — which is exactly why it earns its place: `_stddev_samples` is a hard **0.0**
  for NH22P's late-Holocene window, which holds a single sample, and a whisker of zero there
  would read as a confident measurement rather than an unconstrained one.

`dDraw` and `dDivc` carry no ensemble dimension, so `_stddev_mc` is written empty for them; all
three CSVs keep an identical header either way.

Until the laptop round trip lands, `LGM_analyses.ipynb` falls back to computing the anomaly and
`_stddev_samples` itself from the timeslice means, and draws no Monte Carlo whisker. It prints
which path it took.
